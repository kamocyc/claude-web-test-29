# City Sim

エージェントベースの2D都市シミュレーション。市民を1人1人シミュレートし、
プレイヤーはその中の誰か1人の一日を追いかけることができる。

TypeScript + Vite + Canvas 2D。**ランタイム依存はゼロ**。

```bash
npm install
npm run dev     # http://localhost:5173
npm run test    # Vitest
npm run build   # 型検査 + 本番ビルド
```

## 操作

| 操作 | 内容 |
|---|---|
| 左ドラッグ | 選択中のツールで描く（道路・ゾーンはドラッグで連続して塗れる） |
| 右ドラッグ | マップを動かす |
| ホイール | ズーム（カーソル位置を中心に） |
| クリック（選択ツール） | 建物をクリックすればその建物の情報、それ以外なら近くの市民を選ぶ |
| `1`〜`7` | 選択 / 道路 / 線路 / 駅 / 路線 / 発電所 / 撤去 |
| `8` `9` | バス停 / バス系統 |
| `G` `H` `J` `I` | 学校 / 消防署 / 警察署 / 病院 |
| `U` `Y` `X` | 公園 / 競技場 / 遊園地 |
| `K` `L` | 高架道路 / 高架線路（1回押すごとに1段上がる） |
| `Q` `W` `E` `R` `O` | 低密度住宅 / 高密度住宅 / 商業 / 工業 / オフィス |
| `A` `S` `D` `F` | 農業（水田）/ 林業 / 漁業 / 鉱業 |
| `Space` | 一時停止 |
| `Z` | ゾーン表示の切り替え |
| `0` `T` `P` `N` `V` `C` `B` `M` | オーバーレイ: 通常 / 渋滞 / 電力 / 騒音 / 地価 / 治安 / 公共カバー / 標高 |
| 画面下 `ウィンドウ` | 詳細 / 警告 / 電力 / 財政 / 統計 / 公共 / 路線 / 条例 のウィンドウ開閉 |
| 画面下 `システム` | 保存 / 読み込み / 遊びかた |

画面は Cities: Skylines と同じ組み方にしてある。**上に街の指標**（日時・資金・人口・
雇用・幸福度・電力・鉄道と、いちばん急ぎの警告）、**下に操作**、その間は地図だけ。
情報は固定のサイドバーではなく**ウィンドウ**で、ドラッグで動かせて、畳めて、閉じられる。

はじめの街があらかじめ用意してある。住宅地（西）と商業地（東）が2本の道路と
1本の鉄道だけで繋がった形で、速度 ×3 か ×10 で進めると建物が建ち、人口が増え、
朝になると通勤が始まる。発電所2基と工業地区、そして地形が許した場所に一次産業が
最初から置いてあるが、**わざと足りていない**: 数日で電力が不足し、街が育つと
一次産業も足りなくなる。最初にやることは、電気を増やし、水田・林・鉱床を見つけて
道路で繋ぐことになる。

**この作品の主眼**: 誰か1人をクリックし、`×0.25`（観察速度）にして「カメラで追う」を
オンにすると、その人が家を出て、渋滞に捕まり、職場に着くまでを最初から最後まで
見届けられる。パネルの数字はすべてシミュレーション本体から直接読んでいる。

なお `T` はオーバーレイ（渋滞）に取られているので、オフィスの区画は `O` に振ってある。
キー入力はオーバーレイ表を先に見るので、そこと重なるキーはツールから引けない。

## 下のバーは1列（アイコンとグループ）

ツールバーは**アイコン1列**で、意味ごとに区切ってある —
`選択` `道路` `鉄道` `バス` `区画` `公共` `レジャー` `撤去` `ビュー` `ウィンドウ` `システム`。
以前は文字ボタンが2段に折り返していたので、ウィンドウ幅が変わるたびにボタンの位置が
動いた（狭い画面では `撤去` が別の場所に来る）うえ、地図の1/5を占めていた。順序が
固定なら位置で覚えられるし、幅は1/3で済む。狭いときは折り返さずに横スクロールする —
動かないことのほうが大事なので。

ボタンの名前は**バーの上端の1行**に出る。ポインタを乗せればその名前、乗せていなければ
いま手に持っているツールが出る。ツールチップを1つずつ出すより、名前がいつも同じ場所に
出るほうが読みやすい。

区画のボタンには**その区画の色**が下線として付いていて、地図に塗られる色と一致する。
色そのものも Cities: Skylines に合わせてある —
住宅=緑、商業=青、工業=黄、オフィス=シアン、農業=黄土、林業=濃緑、漁業=水色、鉱業=茶。

## 説明は「？」を押してから出る

画面に**文章の説明は常設しない**。電力網が道路をたどること、地価の上げ方、警告ごとの
対処法 — どれも1度は役に立ち、その後はずっと邪魔になる。数字が動き続ける画面では、
変わらない段落は「読み飛ばす対象」でしかない。

文章はすべて**「？」の後ろ**にある。

| ？の場所 | 出るもの |
|---|---|
| 各ウィンドウのタイトルバー | そのウィンドウの読み方 |
| 警告1件ごと | その警告の対処法 |
| 詳細ウィンドウの「地価の内訳」 | 地価の上げ方 |
| `システム` の `？`（遊びかたウィンドウ） | 操作・ショートカット・電力・路線・地価 |

## 警告は建物の上に出る

うまくいっていない建物には、**その建物の上にアイコンが浮かぶ**（`警告アイコン` で
オン/オフ）。以前は地図の上では動いている工場と止まっている工場が見分けられず、
1軒ずつクリックして回るしかなかった。

| アイコン | 意味 | 対処 |
|---|---|---|
| 火（赤） | 火災発生中（時間切れで建物が消える） | 消防署を建てる、現場までの道路と渋滞を見る |
| 盗（橙） | 盗難発生中 | 警察署を建てる、地価を上げる |
| ⚡（赤） | 電気が来ていない | 発電所を建てるか、道路で電力網に繋ぐ |
| 空（橙） | 商店の在庫切れ / 工場の原料切れ | 工場・一次産業と道路で繋ぐ、渋滞を解消する |
| 人（青） | 働き手がいない | 住宅を増やすか、通勤経路を短くする |

火と盗は**警告アイコンのオン/オフに関係なく出る**。他のバッジは「読みたい人が読む
状態表示」だが、この2つは締め切りのある事件で、見えなかったせいで建物を失うのは
プレイヤーのせいではないため。

1つの建物には**いちばん重い1つだけ**を出す。停電した工場は同時に原料切れでも人手不足でも
あるが、バッジを3つ重ねても最初の1つ以上のことは言っていない。

街全体の警告は `警告` ウィンドウに全部並ぶ。各項目には**「？」（対処法）**と、場所が
特定できるものには**「(x, y) を見る」ボタン**が付いていて、押すとカメラがそこへ飛んで
対象に輪が付く。対処法を8件ぶん並べると一覧ではなく文章の壁になるので、開くのは
知りたい1件だけ。
上のバーに出るのはその先頭1件で、クリックすると同じウィンドウが開く。

地図のバッジとウィンドウの行は同じ判定（`src/sim/diagnostics.ts`）から出ている。
別々に書けば必ずズレるし、ズレた瞬間にどちらも信用できなくなる。

## 車の表示（車線と前後）

車は**左側通行**で、進行方向の左寄りに描かれる。向かい合う2方向は同じタイルでも
決して重ならないので、渋滞がどちら向きの列なのかがひと目で分かる。これは見た目だけの
話ではなく、占有モデル（`occupancy.ts`）が最初から「対向車は前方の障害物ではない」と
扱っていることの可視化でもある。

車体は進行方向を向いて描かれ、**先頭が明るく、後端が暗い**。向きの計算には
「前フレームからの移動量」ではなく**経路そのもの**を使う。赤信号で止まっている車は
移動量がゼロで、タイルに入った直後の車は移動量が丸め誤差しかないため、移動量から
向きを出すとプレイヤーがいちばん近くで見ているときに限ってチラつくからだ。

## 信号機

3方向以上が交わり、かつ南北と東西の両方が繋がっている交差点には自動的に信号が付く。
単なる曲がり角は譲り合う相手がいないので付かない（赤にしても止めるだけ無駄になる）。

- **信号は状態を持たない**。「tick と交差点ごとのオフセットから決まる純関数」であり、
  だから計算量ゼロで、シード再生でも一致し、セーブデータにも書かれない。
  オフセットは位置から決めているので、通りに沿って青が流れていく。
- 1周期は `南北青 → 全赤 → 東西青 → 全赤`。**全赤があるのは踏み込み対策**で、
  信号は瞬時に変わるため「変わった瞬間に、もう止まれない位置にいる車」が必ず存在する。
  そういう車を無理に止めると交差点の**中**で停止してしまい、青になった側を塞ぐ。
  そこで停止距離が足りない車はそのまま通過させ、全赤の間に交差点を空ける。
- 止まると決めた判断は市民に**ラッチする**（`signalHold`）。停止線へは漸近的に
  近づくので「今から止まれるか？」は最後には必ず偽になり、毎tick判定し直すと
  ずっと待っていた車が最後にすり抜けてしまうため。
- 踏切と同じく、**渋滞の逃げ道（一定時間待った車は進入できる）は赤信号には適用しない**。
- 停止位置はタイル境界の**わずか手前**（`STOP_LINE_SETBACK`）。境界ちょうどを狙わせると、
  停止した車は数tickで境界に収束し、収束した時点で「もう次のタイルの中」になる —
  つまり赤信号も踏切も、止まってから5tickほどで**漏れていた**。手前で止めれば、
  待っている間ずっと自分の進入路の中にいるので、止めている規則が効き続ける。

信号を入れた効果は測れる形で出ている。同じ初期タウンを3日回すと、鉄道の延べ乗車は
152人（信号なし）から244人（信号あり）に増える。車が遅くなったぶん、同じ市民が
電車を選ぶようになるからで、モード選択が交通モデルと繋がっていることの傍証でもある。

## 鉄道

`駅`(6) で駅を置き、`路線`(7) で駅を順にクリックして「この順で路線を作る」を押すと、
**足りない線路は自動で敷かれて**路線が開業し、電車が走り出す。線形を自分で引きたい
ときは `線路`(5) で先に敷いておけば、その線路がそのまま使われる。

- **駅は道路に接する空きタイルに置ける**（線路は要らない）。乗客が歩いてくる歩道は
  必須だが、線路は路線を作るときに引かれる。
  以前は線路と道路の両方に接することを要求していたが、それだと「どこに駅を置くか」
  より先に「どう線路を通すか」を決めさせることになり、順序が逆だった。
- **路線ツールが線路を敷く**。ホームのない駅にはホームを与え（歩道の反対側を優先）、
  繋がっていない駅どうしは A* で経路を引いて線路を敷く。曲がるたびに小さなコストを
  足しているので、結果は階段状ではなく鉄道らしい線形になる。水面や建物で繋げない
  ときは**何も残さずに**失敗する（試行中に置いたタイルは全部剥がす）。既存の建物を
  壊すことは絶対にしない。
- **駅での待ち人数と列車の乗車人数を表示する**。マップ上では駅の上に「N人待ち」、
  列車の上に乗車人数が出る。駅を選択ツールでクリックすれば、待ち人数・乗り入れ路線・
  各路線の列車数と乗車人数が出る。右の統計パネルには路線ごとの
  「乗車 / 待ち / のべ乗車」が並ぶ。どれも同じカウンタを読んでいるので食い違わない。
- **路線は往復ルートとして保持する**（A,B,C,B,A で先頭と末尾が同じタイル）。
  こうすると電車は方向フラグも折り返し処理も持たず、ただ進んで端で巻き戻るだけで済む。
- **踏切**: 線路と道路は同じタイルに同居できる。列車が近づくと踏切は閉まり、車は
  停止線の手前で減速して待つ。列車が常に優先で、渋滞の「詰まりすぎたら通す」逃げ道は
  踏切には**適用しない**（待たされたことは線路に進入していい理由にならない）。
  道路網に線路を引くと勝手に踏切になるので、線路が道路で分断されることはない。
- 電車も車と**同じ追従モデル**（`carFollowing.ts`）をパラメータ違いで使っている。
  だからホームから滑らかに発車し、次の駅に滑らかに滑り込む。
- 乗り換えは未対応。乗車駅と降車駅は同じ路線上にある必要がある。

### 市民はいつ電車を選ぶのか

これが本作でいちばん面白いところで、**渋滞と連動している**。

市民は出発時に「**そうしなかった場合の所要時間**」と「停留所まで歩く+待つ+乗る+
降りて歩く時間」を比べて速いほうを選ぶ。比較相手が「車」ではなく「そうしなかった
場合」なのが効いている:

- 車を持っている市民 → 記憶した渋滞込みの**運転時間**と比べる
- 車を持っていない市民（**2割**）→ **歩いた場合の時間**と比べる

この2割が公共交通の市場そのもの。車はドア・ツー・ドアで自由流なら必ず速いので、
同じ道路を同じ速度で走って停留所にも止まるバスは、**時間では車に絶対に勝てない**。
勝てなくてよい: 車のない世帯にとって選択肢は「バス」か「非常に長い徒歩」で、
そこにバスの需要がある。鉄道のほうは専用の線路を走るので、距離が伸びれば車にも勝つ。

車の所要時間を**自由流で見積もると鉄道も構造的に勝てない**。実際に最初はそう実装
していて、路線を敷いても乗客はゼロだった。

そこで `trafficMemory.ts` が**タイルごとに「最近その道が実際どれくらいの速度で
流れていたか」を指数移動平均で覚えている**。市民はその記憶で車の所要時間を見積もる。
結果、モード選択が1日の中で動く:

- 深夜: 道路はガラガラ → 全員が車
- 朝のラッシュ: 幹線が詰まったと記憶されている → 同じ市民が電車に切り替える

「今まさに形成されつつある渋滞」ではなく**記憶**なのは意図的で、通勤者は自分の
ルートがこの時間帯どうなるかは知っているが、コートを着ている間に発生している渋滞は
見えないため。

### 駅をどこに置くかが効く

路線が割に合うかは1本の不等式で決まる:

```
節約 = D × (1/CAR - 1/TRAIN) = 5.5 D
費用 = 徒歩タイル数 / WALK_SPEED + (2D / TRAIN) / 列車数 / 2
```

徒歩は1タイルあたり31 tick、車は8 tick。つまり**駅までの徒歩がすべてを食う**。
両端の駅が住宅・職場のすぐ上にあれば25タイル程度の乗車から割に合うが、駅が
外れた場所にあると50タイル以上でないと勝てない。**駅の立地が最重要の判断**になるのは
意図した設計で、下敷きにしたゲームと同じ性質。

## バス

バスは鉄道と**同じ路線モデルの別モード**で、走る場所だけが違う。停留所の並びも、
往復ルートの持ち方も、乗降も、経路プランナーも1つのコードを共有していて、
違いは1枚の表（`transit.ts` の `MODES`）に集めてある。

|  | 鉄道 | バス |
|---|---|---|
| 走る場所 | 専用の線路 | **他の車と同じ道路** |
| 速度 | 0.4 タイル/tick | 0.125（車と同じ） |
| 定員 | 60 | 30 |
| 停車時間 | 20 tick | 14 tick |
| 車両数 | 4 | 3 |
| 歩いて来てもらえる距離 | 14 タイル | **7 タイル** |
| 停留所/駅の値段 | ¥4,000 | **¥900** |
| 建設 | 足りない線路を自動で敷く | **何も建てない**（道路が繋がっていなければ開業できない） |

### バスは渋滞に「巻き込まれる」

バスは `RoadAgent`（トラックや車と同じインターフェース）として実装してある。
つまり信号で止まり、踏切で待ち、プレイヤーが作った渋滞に**同じように**捕まる。
これがバスをこのシミュレーションに入れる理由そのもので、路線図の上では速そうな系統が
実際には自分の作った渋滞で遅れているところが見える。渋滞が酷くなるほど
（記憶された運転時間が伸びるほど）バスが選ばれるようになるのも、同じ仕組みの裏返し。

### 経路は「宣言」であって「工事」ではない

バスの1区間は、**いまいる場所から次の停留所まで**の普通のドア・ツー・ドア経路として
毎回引き直される。線路を持つ鉄道と違い、バスが走るのは市の道路なので、
プレイヤーが道を1本引き直すたびに系統が廃止されては使い物にならない。

- 経路上の道路が撤去された → **系統ごと引き直す**。繋がっていれば運行は続く
- どうやっても停留所が繋がらない → そこで初めて廃止し、バスを車庫に返す
- 走行中に道路が切れた → そのバスはその場から引き直す（できなければ停留所で待つ）

停留所の間隔は7タイルの徒歩圏を前提にしていて、**密に置くのが正しい**。
1系統の停留所は駅より安く、そのぶん1本あたりの輸送量も少ない。

## 高低差・坂道・立体交差

地面には**高さ**がある。メートルではなく「段」で、0〜6段。この単位を選んだ理由は、
シミュレーションが高さそのものを聞く場面が一度もないから — 聞くのはいつも
**隣のタイルとの段差**で、それが車の登る坂であり、線路が登れない壁であり、
同じタイルに乗った2つの構造物が「同じ場所」なのか「片方が上を通っている」のかを
決める唯一の値になる。

### 坂は速度制限として効く

登り勾配は**そのセグメントの自由速度を下げる**だけで、追従モデルはそのまま動く。
だから坂を登るトラックの後ろで車列が伸びるし、その渋滞は他の渋滞と同じ仕組みで
できている。1段あたり22%、車両ごとの係数付き:

| | 係数 | 1段登ったときの速度 |
|---|---|---|
| 車 | 1.0 | 78% |
| バス | 1.4 | 69% |
| 電車 | 1.6 | 65% |
| トラック | 1.8 | 60% |
| 徒歩 | 1.2 | 74% |

下りに**ボーナスは無い**。下りを速くすると「丘を越える経路」が最速になってしまい、
勾配を入れた目的と逆のことが起きる。

経路探索も同じ関数を使う。1歩のコストは **1 / 速度係数** = その1歩にかかる時間で、
だから「遠回りだが平坦な道」が「短いが丘を越える道」に勝つことがある。逆に、
丘が1タイルだけなら登ったほうが速い — 実際の運転者と同じ判断で、これは仕様どおり。

### 線路は1段しか登れない

道路は何段でも登れる（遅く、しんどいだけ）。線路は**1タイルにつき1段まで**。
この非対称が高低差を入れた理由そのもので、鉄道は等高線に沿うか、遠回りするか、
高架で自分の勾配を保つしかない。路線建設の自動敷設もこの制約込みで探索するので、
登れない斜面には**最初から向かわず**迂回する（最後のタイルで失敗して敷きかけの
線路が残る、ということが起きない）。

### 高架と立体交差

`高架道路` `高架線路` は押すたびに**1段持ち上げる**。ランプは自動では作られない —
必要なら手前のタイルも持ち上げる、それだけ。持ち上げると3つのことが起きる:

- **踏切が消える**。同じタイルに道路と線路があっても、高さが1段違えば
  「同じ場所」ではない。遮断機は下りず、列車が来ても車列は止まらない
- **水を渡れる**。水上に架けた高架は橋で、川の対岸へ行く唯一の方法
- **維持費が段数ぶんかかる**（1段1タイルあたり ¥2/日、建設は道路¥700 / 線路¥1,500）

判定は1か所（`tileMap.isCrossing`）に集めてある。踏切の遮断機も、地図の描画も、
警告も同じ関数を見るので、「ある場所では立体交差、別の場所では踏切」が起きない。

### 高台は良い土地でもある

高さは障害物としてだけあるのではない。周囲より高いタイルには**眺望**が付き、
地価が上がる（1段5点、3段で頭打ち）。丘は「登るのが面倒な場所」であると同時に
「住みたい場所」で、その両方が同じ地形から出てくる。

## 公共サービス（学校・消防・警察・病院）

4つとも「範囲に入ると幸福度が上がる施設」にはしていない。4つは違うものなので、
**違う仕組み**で書いてある。

| 施設 | 質問 | 仕組み |
|---|---|---|
| 学校 | そこへ**通えるか** | 道路をたどった到達圏（電力網と同じ考え方） |
| 消防 | **間に合うか** | 実際に消防車が走る。到着時間は道路と渋滞そのもの |
| 警察 | この街は**安全に感じるか** | 治安の場（騒音・地価と同じ Float32 の場） |
| 病院 | そこへ**かかれるか**、そして**そこに住めるか** | 到達圏（学校と同じ）＋ 環境に押し戻される健康 |

### 学校 → 学歴 → 賃金

学校の到達圏にある住宅の住民は、1時間あたり 0.8 ポイントずつ**学歴**（0〜100）が
上がる。学歴は下がらない: 習ったことは学校が閉まっても引っ越しても残る。

効くのは賃金で、満点の労働力は同じ職に対して **1.5倍**の価値を生む。税はその賃金に
かかるので、学校は「維持費を先に払い、数日後から税収で返ってくる投資」になる。
到達圏は道路をたどるので、**川の向こうの学校は橋ができるまで誰の学校でもない**。

### 消防 → 到着時間

建物には出火の確率がある（工業は4倍、発電所は6倍。消防の圏内なら点検が入るぶん0.6倍）。
出火した建物は**約2.2時間で焼け落ちる**。消防署からいちばん近い（＝実際に走って近い）
空き車両が出動し、到着して 120 tick 作業すれば消し止められる。間に合わなければ
建物は失われ、住んでいた人は**空き家に移るか、街を出る**。

到着時間を「カバー率%」ではなく**車を走らせて**決めているのが要点で、
消防署が渋滞の向こう側にあれば、地図の上では圏内でも間に合わない。
道路が切れていれば出動そのものができない。

### 警察 → 治安の場

治安は騒音と同じ「場」で、人口密度と商店が犯罪圧を生み、**地価の低さ**がそれを増やし、
警察署が半径18タイルぶん引き下げる。治安は3か所に効く:

1. 幸福度の `治安` 項目
2. **地価**（1ポイントあたり0.45を減点。騒音より軽いのは、警察署で取り返せるから）
3. 各建物で**実際に盗難が起きる確率**

盗難はパトカーが間に合えば解決し、間に合わなければ商店の在庫が奪われ、
**その一帯の治安がさらに悪化する**。放っておいた地区が坂を転がるように悪くなるのは
意図した挙動で、断ち切る手段が警察署と地価。

### 病院 → 健康（学歴と逆向きの数字）

病院の到達圏は学校とまったく同じ仕組み（道路をたどる多点BFS）で計算する。
違うのは**カバーされて何が起きるか**のほう。

学歴は上がるだけで、下がらない。習ったことは学校が閉まっても残るので、学校は
「一度建てれば返ってくる投資」になる。健康はその逆で、**行き先の値に向かって
毎時ゆっくり動く**:

```
目標 = （病院が届く ? 92 : 58）− 騒音/100 × 22 − 治安の悪さ/100 × 10
健康 += (目標 − 健康) × 0.18   （1シム時間ごと）
```

つまり病院を建てれば上がり、**潰せば下がる**。幹線道路沿いや治安の悪い地区では
病院があっても目標が下がる。学校が「投資」なら病院は「約束」で、この非対称性が
2つを別のシステムとして書いた理由そのもの。健康は幸福度の項目として直接効き、
公共ウィンドウと統計ウィンドウに平均が出る。

### 車を持たない世帯

公共交通と公共サービスを入れるにあたって、市民に1つだけ事実を足した:
**5人に1人は車を持っていない**。半分ではなく2割なのは、交通モデルのほうの理由が
大きい — 車を4分の1減らすと、このシミュレーションが作ろうとしている渋滞そのものが
静かに消えてしまう。

## 公園とレジャー（3つめの外出目的）

「公園を建てると周囲の幸福度 +N」にはしていない。それだと**誰も公園に行かない** —
道路は午後3時に空のままだし、川の向こうの遊園地は隣の遊園地とまったく同じ価値になる。
レジャーは買い物とまったく同じ形で書いてある。**溜まって減る量**があり、
それを埋められるのは実際の**外出**だけ。

```
c.leisure  余暇の残り（日数）。1時間ごとに 1/24 減る
c.leisure <= 1.0 かつ 開いている時間 かつ その人の時間帯 → 出かける
到着 → visit() で 3日 × 集客力（上限1.5倍）回復。残高の上限も 4.5 日
```

### 行き先は「魅力 ÷ 距離」で決まる

買い物は日用品なので「棚に商品がある一番近い店」でいい。レジャーはそうではないので、
**施設の集客力を移動距離で割った**値で候補を並べ、上位から**いちばん近いもの**を選ぶ。

| 施設 | 建設費 | 維持費/日 | 集客力 | 1日の受入 | 職 | 騒音 | 地価への効き |
|---|---|---|---|---|---|---|---|
| 公園 | ¥3,500 | ¥120 | 1.0 | 240人 | 0 | 0 | **+16 / 半径7**（最強・最狭） |
| 競技場 | ¥45,000 | ¥2,100 | 2.4 | 1,320人 | 14 | 7 | +10 / 半径12 |
| 遊園地 | ¥90,000 | ¥3,200 | 3.4 | 2,160人 | 20 | 6 | +10 / 半径12 |

20タイル離れると魅力は半分に見える（`LEISURE_DISTANCE_BIAS`）。だから
**住宅地の中の小さな公園がいちばん効く**一方、遊園地は川を渡ってでも人を呼ぶ。
公園がゲーム内で最も安い公共建築なのは意図で、財政が苦しい街が
「不満な地区に対して打てる唯一の手」であってほしいから。

### 満員という失敗

施設には1日の受入数があり、超えると**入れずに帰る**（`lastOutingFailed`）。
これは商店の棚が空だったときとまったく同じ扱いで、満足度に跳ね返る。
1つの巨大施設が街全部の面倒を見られないようにするためのもので、公共ウィンドウの
「本日の来場 / 入れなかった世帯」がその失敗を数字で出す。

### 週に1日の休み

市民は**週に1日休む**。曜日は `seed` から決まるので**人によってばらばら**で、
どの日も人口の約1/7が休んでいる。街全体で土日を休みにすると、経済が7日周期で
がくんと動くだけで、街の作り方については何も語らない。ばらばらにすると
欲しかったものだけが残る — 平日の昼間に家にいて、公園に出かける人。

休日の市民は出勤せず、開園時間中ならいつでも出かける。詳細ウィンドウには
その人の休みの曜日が出る。

## 条例（5つの政策）

条例は**すでに動いている仕組みの数字を1つ動かす**ものだけにしてある。
独自の仕組みを持つ条例は「目に見えないもう1つのゲーム」になってしまうので、
効果は必ずプレイヤーが元から見ていたパネルに出る。

| 条例 | 動かす数字 | 出るところ | 費用 |
|---|---|---|---|
| 運賃補助 | 公共交通が勝つ閾値 ×1.25 | 統計（移動手段の内訳） | 前日の乗車人数に比例 |
| 省エネ条例 | 全建物の消費電力 ×0.85 | 電力ウィンドウの需要 | 建物数に比例 |
| 夜間パトロール | 警察署の治安改善 +22 | 治安オーバーレイ | 人口に比例 |
| 緑化条例 | 公園の地価効果 ×1.5、集客力 ×1.25 | 地価の内訳 | 公園の数に比例 |
| 無料健診 | 病院圏の健康の目標 +10 | 公共ウィンドウの平均健康 | 人口に比例 |

費用が**定額ではなく街の規模に比例する**のも意図。定額だと大都市では無料、
小さな街では致命的になり、どの条例も「開始直後に一度決めれば終わり」になる。

条例の請求は**建設費ではなく維持費と同じ扱い**で、残高が足りなくても止まらずに
引き落とされる。赤字にすれば利息がつき、住民も気づく（幸福度の `solvency` 項）。

## 路線ウィンドウ（見る・直す）

以前は路線は「作ったら最後、そのまま生きるもの」だった。どの駅を通るのかは
地図上で駅を1つずつクリックしないと分からず、街が育って1駅足りなくなっても
足す方法がなく、そして交通事業者が実際に毎日する判断 — **この路線、増発すべきか？** —
に答える場所がどこにもなかった。

路線ウィンドウは鉄道もバスも1つの表に出し、その判断材料を**押すボタンの隣**に置く。

- 行をクリック → 地図で**その路線だけ**が濃く出る（他は薄くなる）。停留所には丸が付く
- 出る数字: 停留所数・車両数・いま乗っている人・待っている人・
  **平均待ち時間**・**一周の時間**・のべ乗車人数
- できる操作: **増便 / 減便**（最大8・最小1）、**改名**、**色変更**、
  **停留所を編集**、**廃止**、停留所をクリックして地図へ飛ぶ

待ち時間と一周の時間は、経路探索が乗り換え判断に使っているのと**同じ関数**
（`expectedWaitTicks` / `lapTicks`）から出している。増便すれば、不満だったその数字が
その場で動く。

### 停留所の編集は「路線ツールをもう一度使う」

「停留所を編集」を押すと、**いまの停留所が選ばれた状態で路線ツールに切り替わる**。
そこから駅を足したり（一覧にある駅をもう一度クリックして）外したりして
「この順に変更する」を押すと、`reshapeLineThrough` が経路を引き直す。

- 鉄道なら足りない線路を敷く。敷けなければ**敷いたぶんを全部戻して**元の路線のまま
- バスなら道路が繋がっているかだけを見る。繋がっていなければ元のまま
- 成功した場合、**路線IDも名前も色ものべ乗車人数もそのまま**。変わるのは経路と停留所だけ

新しい路線を作らせて古いのを廃止させることもできたが、それでは名前も色も
それまでの実績も消える。「同じ路線が伸びた」という出来事は、別の路線ではない。

車両は同数のまま新しい経路に置き直される。1台だけ止まる、といった中途半端な状態を
作らないために、車両の出し入れは `retireVehicle` 1か所に集約してある
（廃止・減便・経路変更が「車両が止まるとは何か」について食い違えない）。

## 市民の統計

右パネル下段に、いま街で何が起きているかが常時出る。

- **人口・就業・求人**
- **いま何をしているか**: 在宅 / 勤務中 / 移動中 / 買い物中 / レジャー中 / 駅で待ち /
  乗車中 / 経路なし
- **移動手段（外出中）**: 徒歩 / 車 / 電車
- **幸福度**: 総合と、その内訳（住環境・通勤・雇用・買い物・電気・治安・公共・
  レジャー・健康）、直近1時間の転入/転出、住宅の空き
- **都市の状態**: 電力の需要と供給、停電中の建物、平均地価、平均犯罪度、平均学歴、
  平均健康、商品の供給率、一次産業の産出・工場の生産・売れた商品・在庫切れの商店・
  原料切れの工場
- **物流**: 走行中のトラック台数、輸送中の商品、本日の配送件数と単位、平均配送時間、
  届いていない需要、立ち往生している台数
- **完了した移動**: のべ件数と、直近300件の平均所要時間（手段別）・平均待ち時間
- **路線ごと**: 乗車 / 待ち / のべ乗車

トラックをクリックすると、積荷・所属・行き先・残り距離・速度が出る。工場や商店を
クリックすれば「入荷予定」「出荷中」が出る — 積み込んだ瞬間に在庫が減るので、
これがないと「商品が消えた」ように見える。

その上に**財政パネル**（残高・借入・前日の内訳・税率・借入操作）がある。

この2種類の数字は性質が違うので、意図的に分けてある。上の3つは**その tick の
数え直し**なので画面と絶対にずれない。下の2つは**履歴**で、移動が終わってはじめて
1件として計上される。街は「賑わって見えるのに機能していない」状態になり得るので
（何百人も動いているが全員が列に並んでいる）、それを見分けられるのは
完了した移動の平均所要時間だけになる。

## セーブ / ロード

HUD の `保存` / `読み込み` でブラウザの localStorage に街を保存・復元する。

保存するのは**再計算できないものだけ**: マップ5層（地形・道路・線路・区画・資源、
base64）、建物（在庫つき）、市民（進行中の経路・乗車中の行程・幸福度・恒久ID）、
路線と列車、**トラック（積荷と行き先ごと）**、資金と借入と税率、RNG のストリーム位置、
各処理の進捗、そして**渋滞の記憶・騒音・地価**。信号の位相は tick の関数、電力網・占有・踏切・
経路キャッシュは読み込み直後に再構築されるので書かない。

渋滞の記憶だけは「導出できないのに落としたくなる」典型なので明示的に入れている。
これを捨てると、読み込み直後は全部の道が空いて見えるため、数シム時間ぶん全員が
車に流れてしまい、**同じ街ではなくなる**。

同じ理由で入れているものが3つある。市民の**余暇と健康**（家計の食料と同じで、
どちらも数日かけて動く量なので導出できない）、施設の**本日の来場者数**（今日はまだ
終わっていない）、そして**騒音の集計途中のタリー**。最後のものは、レジャーと健康を
入れたときに同一性テストが見つけたバグでもある: 騒音は毎tickタリーを貯めて1時間ごとに
場を作り直すので、タリーを捨てると読み込み直後の1時間だけ「静かな街」の値になる。
そのわずかな差が地価と健康を経由して街全体をずらしていた（健康は平滑化された
累積値なので、以前の指紋では見えていなかった）。

条例も**導出できないもの**としてセーブに入る。加えて、運賃補助の請求根拠になる
「前日の締め時点でののべ乗車人数」も入れる — 入れないと、ロードのたびに1日ぶんの
補助がタダになる。

テストでは、保存→復元した街が**元と1ビットも違わない**こと、さらに復元後に同じ
tick 数だけ進めても両者が**完全に一致し続ける**ことを確認している。この不変条件は
実際に役に立っていて、`lastGrowthBucket` を保存し忘れていたバグ（読み込むたびに
成長が1回余分に走り、街が少しずつ膨らむ）はこのテストが捕まえた。

## 区画と地形

区画は9種類:

| 区画 | 建つもの | 備考 |
|---|---|---|
| 低密度住宅 | 住宅（4人） | どこでも |
| 高密度住宅 | 集合住宅（16人） | **地価が55以上**の土地にしか建たない |
| 商業 | 商店（6人雇用） | 商品を仕入れて売る。税は売上に対してかかる |
| 工業 | 工場（10人雇用） | 原材料を商品に変える |
| オフィス | オフィス（12人雇用） | 商品を必要とせず、静かで、給与が高い |
| 農業（水田） | 水田（4人雇用） | **肥沃な土地**（川沿い）だけ |
| 林業 | 林業所（4人雇用） | **森林**だけ |
| 漁業 | 漁港（4人雇用） | **水に接するタイル**だけ |
| 鉱業 | 鉱山（6人雇用） | **鉱床**だけ |

一次産業だけは置ける場所が地形で決まる。これは制限ではなく**地図に意味を持たせる
ための仕掛け**で、平坦で均質な土地には「ここに置きたい」という理由が生まれない。
肥沃な土地は川がつくるので川沿いに帯状に伸び、森と鉱床はいくつかの塊として散らばる。
どこに一次産業を置くかが決まると、それを工場に繋ぐ道路と、工場を商店に繋ぐ道路が
決まり、街の骨格がそこから決まっていく。

建物の性能は `src/world/buildings.ts` の**1枚の表**にまとまっている（雇用・電力・
騒音・原材料・産出・貯蔵・維持費・給与）。分岐ではなく表なので、種類を足すのは
行を足すことであり、経済のバランスは数字を並べて眺めれば分かる。

## 供給網（一次産業 → 工業 → 商業 → 家庭）

段は4つ、**全部が実際の移動**になっている:

1. **一次産業**が地面から原材料を生む（水田・林業・漁業・鉱業）
2. **トラック**が原材料を工場へ運ぶ
3. **工場**が商品に変え、**トラック**が商店へ運ぶ
4. **市民**が買い物に出かけ、商店の棚から買って帰る

かつてここは在庫の引き算だった。消費者が「同じ道路網にいて90タイル以内の、いちばん
近い在庫のある供給元」から必要量を瞬時に引き抜く。合計は正しく出るが、それ以外は何も
起きない — 距離はタダ、渋滞は無関係、そしてプレイヤーが引いた道路は、それが支えている
はずの経済を**1単位も運んでいなかった**。

いまは荷物が走る。配送は1台ずつが車と同じ追従モデル・同じタイル占有・同じ信号と踏切に
従う車両で、`RoadAgent` として市民の車と同じコードの上を走る。だから工業地区を渋滞した
幹線の向こう側に置けば、商店は本当に品切れになり、直し方は数字ではなく**道路**になる。

到達可能性も文字どおりになった。「同じ連結成分か」ではなく「**トラックが往復できるか**」
であり、その判定は記憶された速度で価格付けされるので、**渋滞は工場の商圏を実際に縮める**。
90タイルという上限は消え、`MAX_DELIVERY_TICKS`（往復にかけてよい時間）に置き換わった。

### 配車

消費者プル。在庫が減った建物が発注し、いちばん**残り時間が短い**ものから捌く。配車は
完全に決定的（RNGを引かない・建物はid順・同点はidで解決）で、そうでないとセーブの
完全一致継続が壊れる。

### 測って決めた4つ（どれも最初は失敗している）

- **トラックの最高速度は車と同じ**。1方向1車線・追い越しなしのモデルでは、遅いトラックは
  「じゃまな車」ではなく**動く通行止め**になる。36台で人口1000人の街が完全にロックし、
  深夜0時に700人がまだ列の中にいた。トラックが街に払わせるのは速度ではなく、
  **占有する道路と、往復にかかる時間**。
- **車両数の上限は28台**。配送が遅い→需要が満たされない→トラックを増やす→もっと遅く
  なる、というフィードバックが回る。上限120では自分で自分を渋滞させ、100台が列に並んだ
  まま供給網が餓死した。
- **発注は「不足量」ではなく「残り時間」順**。工場の原材料置き場は商店の棚より深いので、
  不足量で並べると空の工場が必ず空の商店に勝ち、街中のトラックが工場へ鉱石を運び続け、
  その工場が作った商品は積み上がったまま商店が干上がる。
- **成長は供給網を消費量に合わせる**。瞬間移動の頃は余剰の工場は無害だったが、車両数が
  有限だと「4倍の工場」は幻の需要としてトラックを食い尽くす。商店も同じ理由で人口比に
  制限した（1000人の街に商店140軒は、埋めるべき棚が140個あるということ）。

### 買い物

家庭は「食料の備え」を持ち、毎時減る。少なくなると夕方に買い物へ出る — 徒歩か車か
電車かは通勤とまったく同じモード選択なので、**近所に商店があるかどうかが交通に効く**。
商業税は実際の来店から生まれる。幸福度の「食料」項も、街全体の供給率ではなく
**その世帯の戸棚**を見る。

暴走を止める仕掛けが3つあり、これも全部一度失敗している:

- **棚が空の商店には出かけない**。これがないと、産業のない街は人口の4割が空の商店へ
  往復し続ける。品切れは**空腹**として現れるべきで、渋滞として現れるべきではない。
- **一度出かけたら数時間は行かない**。半端にしか買えなかった人が、店先で回れ右して
  すぐまた出かけてしまう。
- **買い物の時間帯は4時間幅**（通勤は30分）。30分幅だと大半の人はその間ずっと帰宅途中で、
  結局一度も買い物に行けない。

## 電気

発電所を建てると、その発電所が繋がっている**道路網**の建物に電気が行く。送電線の
レイヤは用意していない — **ケーブルは道の下を通っている**という割り切りで、これは
手抜きではなく設計判断:

- プレイヤーがすでに考えている道路網が、そのまま送電網になる
- 遠くの鉱山地区を繋ぐ手段が「道路をもう1本」ではなく「道路」になる
- 電気の来ていない飛び地が、**地図を見れば理由の分かる**状態になる

同じ網の中では経路を追わず、容量を**プールして id 順に配る**。足りなければ新しい
建物から順に停電するので、街が「ちらつく」のではなく「成長が止まる」形で不足が見える。

`電力` ウィンドウに **供給 / 需要 / 不足 / 余力 / 使用率**と、道路網ごとの内訳が出る。
不足は「需要 − 供給」ではなく**道路網ごとの不足の合計**。電気は繋がっていない道路網の
間を流れないので、北に発電所が余っていて南の鉱山地区が真っ暗な街は、合計が釣り合って
いても**不足している**。1本の数字ならその街を「正常」と表示してしまう。
不足しているときは「あと何か所建てれば足りるか」も出す。上のバーの `電力` チップは
常に `供給/需要` を出し、不足があれば赤くなる。

停電した建物は**何もしない**: 商店は売らず、工場は作らず、給与も税も生まれない。
電気は「あれば少し嬉しい」ではなく、経済が動くための前提になっている。

## お金

| | |
|---|---|
| 建設費 | 道路 ¥45/タイル、線路 ¥120/タイル、区画 ¥25/タイル、駅 ¥4,000、発電所 ¥22,000、撤去 ¥15 |
| 維持費（毎日） | 道路 ¥0.5/タイル、線路 ¥1.5/タイル、駅 ¥300、発電所 ¥900 |
| 税収（毎日） | 住宅税=給与、商業税=売上、工業税/オフィス税=給与。税率は0〜30%で調整可能 |
| 借入 | ¥50,000単位、上限¥400,000、日利0.4%。マイナス残高は日利2%の"無断借入" |

2つの規則がこれをただのカウンタから引き離している。**建設は払えなければ拒否される**
（だから敷ける道路網は、払える道路網でしかない）。一方**維持費は拒否されない** —
残高がなくても引き落とされ、マイナスになれば利息がつき、市民の幸福度が下がる。
建設は貯めれば済む一度きりの支出だが、維持は永遠に続く。だから「道路をどれだけ
広げるか」が判断になる。

税は**存在する建物ではなく、実際に生産されたもの**にかかる。停電した工場も、原材料
の来ない工場も、誰も雇っておらず何も納めない。供給網の断絶が、産業パネルの数字では
なく**予算の穴**として現れるのはこのためで、財政パネルの「前日の内訳」を見れば
どの段が壊れているかが分かる。

## 騒音・地価・幸福度・人口移動

この4つは1本の因果の鎖になっていて、シム内1時間ごとにこの順で走る:

```
電力 → 供給網 → 騒音 → 地価 → 幸福度 → 人口移動 → 成長
```

**騒音**は交通と産業の両方から出る。道路の騒音はそのタイルが実際に運んだ**交通量**から
出て、トラックは車の1.5台分として数える。だから「大型車をどこに流したか」は比喩ではなく、
工場から商店への配送ルートを住宅地に通せば、そこが実際にうるさくなる。時間方向に平滑化しているのは、ある瞬間の車の数で土地を値付けするのは
乱暴すぎるからで、欲しいのは「この場所はふだんどれくらいうるさいか」のほう。

**地価**は基準値40から始まり、次の項目の足し算で決まる（`src/sim/landValue.ts`）:

| 要因 | 効果 | 届く範囲 |
|---|---|---|
| 水辺 | 水タイル1枚につき +10 ×（距離減衰） | 6タイル |
| 森 | そのタイル自身が森なら +6 | そのタイル |
| 駅 | 1駅につき +22 ×（距離減衰） | 10タイル |
| 商店 | 1軒につき +8 ×（距離減衰） | 8タイル |
| オフィス | 1軒につき +4 ×（距離減衰） | 8タイル |
| バス停 | 1か所につき +6 ×（距離減衰） | 5タイル |
| **公園** | 1か所につき **+16** ×（距離減衰） | **7タイル** |
| 競技場・遊園地 | 1か所につき +10 ×（距離減衰） | 12タイル |
| 騒音 | **騒音値 × 0.6 を引く**（交通・工場・鉄道・鉱山） | 騒音場そのもの |
| 治安 | **犯罪度 × 0.45 を引く**（騒音より軽い＝警察署で取り返せるから） | 治安場そのもの |

距離減衰は `1 − 距離/(範囲+1)` の線形。合計を 0〜100 に丸めたものが**落ち着く先**で、
実際の地価はそこへ毎更新25%ずつ近づく（地価は測定値ではなく評判なので、ゆっくり動く）。

つまりプレイヤーが直接触れる値ではなく、**それまでにやったこと全部の合計**になっている。
建物や市民をクリックすると、詳細ウィンドウにこの内訳がそのまま出る —
「駅が近い +21 / 騒音 −4 → 落ち着く先 57」のように、どれが効いていてどれが足りないかが
数字で読める。表示は場そのものと同じ式・同じ減衰から出しているので、
パネルと地図が食い違うことはない（`factorsAt`）。

そして2箇所に跳ね返る: 地価の低い土地には**集合住宅が建たない**し、地価の低い土地の
住民は**幸福度が下がる**。住宅地の隣に工業地区を置く判断の結果が、数字ではなく
街の姿として返ってくる。

**幸福度**は隠れた曲線ではなく、プレイヤーが動かしたものの足し算で組み立ててある:

| 要素 | 重み | 中身 |
|---|---|---|
| 住環境 | 22% | 自宅の地価 − 騒音 |
| 通勤 | 16% | **実際にかかった時間**（3時間で0点。無職なら中立の50） |
| 雇用 | 13% | 仕事があるか |
| 買い物 | 11% | **その世帯が**食料を買えているか（街全体の供給率ではない） |
| 電気 | 11% | 自宅に電気が来ているか |
| 治安 | 9% | 自宅の治安（犯罪度の裏返し） |
| 公共 | 7% | 学校42 / 消防30 / 病院28 が自宅に届いているか |
| レジャー | 7% | **その世帯が**出かけられているか |
| 健康 | 4% | その人の健康（病院と住環境の結果） |

（赤字のときは全員に −12。街が自分の維持費を払えていないのは、住んでいれば分かる）

重みの合計が100%なのは意図的で、項目を足すときは**他から取る**。足し算で増やすと、
同じ「幸福度70」が版によって別の意味になってしまう。

**人口移動**がその帰結。魅力のある街には人が移ってきて、空き家が埋まる。幸福度が
30を下回る状態が**48時間続く**と、その市民は街を出ていく（我慢の期間があるのは、
一晩の不調で街が空にならないようにするため）。**人口は増えるだけの数字ではない**。

退去は1時間に1度まとめて処理し、そこで市民配列を詰め直す。id は配列添字であり
建物と列車が保持しているので、詰め直しは**1箇所に集約**してある。ただし通勤時刻は
id ではなく市民ごとの `seed` から導く: id から導くと、**隣人が引っ越しただけで自分の
生活時間がずれる**という馬鹿げたことが起きる。

## 時間スケールについて（設計上いちばん重要な判断）

物理的に正しい車速・短い1日・観察できる画面速度は、**同時には成立しない**。
3つは1本の式で縛られている:

```
D (通勤距離 tiles) = V (画面速度 tiles/実秒) × L (1日の実時間 秒) × C (通勤所要 シム分) / 1440
```

タイル=8m・車40km/h を素直に入れると、1シム分で83タイル進む。128タイルのマップを
2 tick で横断してしまい、タイル占有ベースの交通は成立しない。

そこで本作は **km/h をモデル化しない**。tick が唯一の時間基準であり、時計も速度も
到着予定時刻もすべてそこから導出する。定数は `src/config.ts` に根拠つきで集約:

```
TICK_HZ = 16, SIM_SECONDS_PER_TICK = 9   → 144倍速 → 1日 = 10分（実時間, ×1）
CAR_FREE_SPEED = 0.125 tiles/tick        → 2.0 tiles/実秒
```

検算: 40タイルの通勤 = 320 tick = **実時間20秒 / シム内48分**。
両方とももっともらしく、`0.125 < 0.5 tiles/tick` なのでタイルを飛び越すこともない。

物理的には自己整合しないが、プレイヤーが知覚する3点 — 車の画面上の速さ、時計の進む
速さ、通勤が1日に占める割合 — はすべて妥当な値に収まる。Cities: Skylines も同種の
割り切りをしている。

**メートル表示をあえて持たない**のはこのため。7タイルの徒歩は33シム分で、
「7ブロック」なら自然だが「56メートル」だと嘘になる。距離はタイルで表示する。

## 渋滞は係数ではなく創発する

このコードベースに「混雑係数」は存在しない。各車が速度 `v` を持ち、車追従モデルで
毎 tick 更新される（`src/sim/carFollowing.ts`）:

```
vDesired = min(freeSpeed, brake(前方車との車間), brake(停止点までの距離))
v += clamp(vDesired - v, -DECEL_MAX, +ACCEL)
s += v
```

`brake(d)` は「距離 d で停止できる速度」。教科書の `sqrt(2ad)` ではなく
`sqrt(a² + 2ad) - a` を使っている。位置は `s += v` で1 tickにつき1回しか更新されない
ため、再判断する前に1 tick 分まるごと進んでしまう。その1歩を織り込んだのが後者で、
これが「停止線でぴたりと止まる車」と「毎回はみ出す車」の差になる。

結果として、渋滞は外挿ではなく **前が詰まった結果として発生し、後方へ波として伝播する**。
渋滞オーバーレイ（`T`）が表示しているのは、そのタイル上にいる車の
`v / freeSpeed` の平均そのもの。

信号のない交差点は暗黙の譲り合い（タイル定員 + 直交方向への譲り）で捌く。相互ブロックで
永久ロックしないよう、一定時間停止し続けた車は定員と直交交通を無視して進入できる
（同方向の車間だけは常に守るので、追突は起きない）。信号のある交差点では、この
逃げ道は**赤信号には効かない**。

### 譲り合いは「車長に依存しない停止距離」で表す

直交交通への譲りは、かつて「交差点の中ほどにいる先行車との車間」として表現していた。
これが**トラックだけが交差点で永久に止まる**バグの正体だった:

- 車間から引かれるのは自分の**車長 + 最小車間**。車（0.25+0.15）はまだ隙間があると
  判断して交差点にじりじり入れるが、トラック（0.45+0.15）は隙間が負になり必ず止まる。
- そのトラックは完全停止はせず、1tickに10⁻³タイルずつ**這う**。当時の「立ち往生」判定は
  `v < 1e-4`、つまり**完全停止**だけを数えていたので、這っている限り渋滞の逃げ道は
  永久に発動しない。交差点が空かない限り、そのトラックは丸一日そこにいた。

いまは譲りを**停止点までの距離**として表す（`GIVE_WAY_NOSE_IN`）。距離は車の鼻先で
測るので車長に依存せず、車もトラックも同じ場所で止まって同じように進む。あわせて
立ち往生の判定を2つ直した: **自由速度の2%未満は止まっていると数える**（這いは進行ではない）、
そして**逃げ道はタイルを1枚進むまで解除しない**（一度動いた瞬間に解除すると、
1/100タイル進んでまた詰まり、60tick待ち直すラチェットになる）。

回帰テストは `src/__tests__/intersection.test.ts`。交差点が**一度も空かない**状況で、
車もトラックも200tick以内に抜けることを確認する（修正前は車45tick、トラックは4000tickでも
抜けなかった）。

この修正で信号と踏切が本当に車を止めるようになったぶん、道路の捌ける量は
テスト街で**2〜3割落ちた**。赤信号をすり抜けて稼いでいた分だったので、これは
バグ修正の代償ではなく、バグの利得が消えただけ。

設計上の要点:

- **タイルネットワーク** はノード = タイル1枚。128² = 16,384 ノードなので A* に十分速く、
  設置/撤去は「そのタイルと4近傍だけ」の差分更新で済む。道路と線路は同じ
  `TileNetwork` を別レイヤに被せただけなので、差分更新もキャッシュ無効化も A* も共通。
- **経路キャッシュ** は家↔職場の往復が大半なのでヒット率が非常に高い。道路グラフの
  `version` が変わったら全破棄する（部分無効化は割に合わない）。
- **経路探索は自由流コストのみ**。渋滞を混ぜないのでキャッシュが安定し、かつ市民が
  実際に渋滞にハマる。それが観察の対象になる。
- **占有情報は毎tick作り直す**。差分更新はタイル跨ぎ・再経路・撤去のたびに漏れる。
  作り直せばその一群のバグが消え、tick が順序非依存になり、決定性テストが成立する。
- **市民はプレーンなオブジェクト配列**。2,000体では十分速く、可読性が段違い。
  SoA/TypedArray 化は必要になってからで良い。
- **電車の乗車は「脚(leg)」で表現する**。`path` には常に「いま自分の足で移動している
  区間」だけを入れ、乗車中の区間は別フィールドに退避する。こうすると移動系のコードは
  電車の存在を一切知らないままで済む。
- **職場の割り当ては近い順ではなく距離で重み付けした抽選**。最初は「最寄り」で実装して
  いたが、それだと全員が数ブロック先で働くことになり、幹線の渋滞も鉄道も需要が生まれない。
- **描画は tick 間補間**。`×0.25` では tick が 4Hz まで落ちるため、補間なしでは
  観察モードがカクつく。
- **信号は状態ではなく関数**。位相を持たせないので、決定性も、セーブデータの小ささも、
  計算量も同時に手に入る。持つのは「どのタイルが交差点か」だけで、それも道路網の
  `version` が変わったときにしか作り直さない。
- **重い処理は tick ではなくシム内時間で回す**。電力は30分ごと、供給網・場・幸福度・
  人口移動・成長は1時間ごと。順番は因果そのもので、前の時間の答えを使うと
  パネルと地図が食い違うのがそのまま見える。
- **建物の性能は1枚の表**（`buildings.ts`）。種類の追加が「switch を探して回る」では
  なく「行を足す」になり、経済のバランスを一目で比較できる。
- **場（騒音・地価）は Float32Array 1枚 + 時間方向の平滑化**。瞬間値ではなく
  「ふだんどうか」を持つので、住む場所を選ぶ判断材料として使える。
- **道路を走るものは1つのインターフェース**（`RoadAgent`）。市民の車とトラックは
  追従モデルも占有も信号も踏切も共有し、違うのは「プロファイル（速度・加減速・車長）」
  だけ。並行実装がないので、片方だけ挙動がずれることが起きない。
- **占有レコードは自己完結**。速度比と占有幅をその場に持つので、誰も
  `world.citizens[占有者.id]` を引き直さない（トラックを入れた瞬間に壊れる書き方だった）。
- **市民の恒久 ID は配列添字とは別**（`seed`）。退去で配列を詰めても、通勤時刻の
  ような「その人固有のもの」が動かない。
- **高さは「段」で持つ**。メートルを持たせると、聞かれてもいないことを答えることに
  なる。実際に必要なのは隣との段差だけで、それは車の坂・線路の限界・立体交差の判定の
  すべてに同じ単位で使える。
- **坂の効果も1つの関数**（`gradient.ts`）。移動の速度と経路のコストが同じ式から
  出るので、「その道を選んだ理由」と「実際にかかった時間」が食い違わない。
  経路コストは *1/速度係数* = その1歩の所要時間そのもの。
- **立体交差の判定は1か所**（`isCrossing`）。遮断機・描画・警告が同じ関数を見るので、
  同じ場所が踏切だったり立体交差だったりしない。
- **地形は生成後に固定**。整地ツールは出していない。高さを後から変えられるなら、
  それは制約ではなく提案になってしまう（開幕の街だけは、街を建てる前に整地している —
  現実の造成と同じで、そうしないと最初の線路が途中で敷けなくなる）。
- **バスと電車は1つの路線モデル**。停留所の並び・往復ルート・乗降・経路探索は共通で、
  違いはモード表1枚（速度・定員・停車時間・徒歩圏）と、ルートを線路の上に引くか
  道路の上に引くかだけ。バスを別システムとして書けば、乗降モデルが2つ・
  「この車両は目的の停留所に本当に着くのか」の判定が2つになり、片方だけ壊れる。
- **バスは特別扱いされない道路車両**。`RoadAgent` なので信号・踏切・追従・占有を
  車と共有する。だから「自分で作った渋滞に自分のバスが捕まる」が成立する。
  消防車とパトカーも同じ理由で `RoadAgent`。**到着時間は仕様ではなく結果**。
- **公共サービスは4つとも別の仕組み**。学校＝道路をたどる到達圏、消防＝実際に走る
  車両、警察＝場、病院＝到達圏＋環境に押し戻される値。「範囲に入ると幸福度+N」に
  統一すれば実装は4分の1で済んだが、それは4つの違うものを1つにしただけで、
  街を作る判断も1つに潰れる。
- **外出の目的は「溜まって減る量」で表す**。通勤は時刻表、買い物は食料、レジャーは
  余暇 — どれも「施設が近くにあると幸福度+N」ではなく、**実際に出かけた**ことでしか
  埋まらない。だから公園は道路と時間帯とキャパシティの問題になり、午後の道路に
  通勤とは別の流れができる。買い物とレジャーがほとんど同じ形なのは意図で、
  違うのは選び方だけ（日用品は最寄り、行楽は魅力÷距離）。
- **条例は新しい仕組みを持たない**。5つとも「すでに動いている数字を1つ動かす」だけで、
  効果は元からあるパネルに出る。独自の仕組みを持たせると、目に見えないもう1つの
  ゲームが裏で走ることになる。費用が定額ではなく街の規模に比例するのも同じ理由で、
  定額だと「開始直後に一度決めれば終わり」になる。
- **路線は作ったあとも編集できる**。改名・色・増減便・経路変更・廃止。経路変更は
  新しい路線を作るのではなく**同じ路線を書き換える** — 名前も色ものべ乗車人数も
  「その路線が積み上げたもの」で、1駅足したくらいで消えていいものではない。
  そして失敗したら**元の路線がそのまま残る**（敷いた線路も戻す）ので、試すのが安全。
- **車両が「止まる」場所は1か所**（`retireVehicle`）。廃止・減便・経路変更が
  それぞれ後始末を書けば、必ずどれかが「もう路線に載っていないのに走り続ける列車」を
  作る。乗客を歩道に戻すのも、スロットを次の路線に返すのも、同じ関数の中にある。
- **家を失った市民は宙に浮かせない**。火事や撤去で住居が消えたら、空き家に移すか、
  移れなければ街を出る。取り残すと「存在しない住所から出発しようとして経路探索に
  失敗し続ける市民」になり、永久に道端で立ち往生する。
- **警告は1箇所で判定する**（`diagnostics.ts`）。地図のバッジ、上バーのティッカー、
  警告ウィンドウ、建物の詳細に出る帯は、すべて同じ関数の戻り値。
- **閉じているウィンドウは更新しない**。開いていて畳まれていないパネルだけが
  毎フレーム数字を組み直す。
- **説明はパネルの本体ではなくウィンドウ側に置く**。本体は毎フレーム作り直されるので、
  そこに静的な文章を入れると数字と一緒に捨てられ、「開いたかどうか」も消える。
  タイトルバーの「？」が持つ要素なら1度書けば済む。
- **アイコンは絵文字ではなく描く**。絵文字は環境ごとに姿が変わり、道路にも区画にも
  ブルドーザーにも対応する絵文字が無い。パスで描けば `currentColor` が効くので、
  選択中の見た目のために2枚目の画像を持つ必要もない。
- **初期状態はアプリの外に出してある**（`world/scenario.ts`）。`main.ts` の中にあると
  「新規ゲームから普通に遊べるか」をテストする手段が無くなる — アプリと同じ関数を
  テストが呼べることが、そのテストが意味を持つ条件。

## テスト

```bash
npm run test
```

いちばん上に置いているのは **新規ゲームのテスト**（`newGame.test.ts`）。他のテストは
すべて「測りたいものに合わせて組んだ街」から始まる — 1車線のボトルネック、最初から
回っているコンパクトな街、何もない交差点 — が、それだとプレイヤーが最初に問う
「新規ゲームを始めて普通に遊んだら、街は育つのか？」には誰も答えていない。
部品が全部通っていても、全体としては2日目で止まることも、誰も通勤できない街に
育つこともある（実際、このテストを書いている最中に両方起きた）。

そこで**実際に出荷している初期状態**（アプリと同じ `newGame()`）から始めて、
人が最初の1時間にやることをそのままやる自動プレイヤー（`autopilot.ts`）に渡す:

- 電力が不足したら発電所を建てる
- どの区画も「空きが一定数」を切ったら区画を足す（成長は**区画済みの土地にしか**建たないので、
  工場を置く場所がない街は、商店がいくら空になっても直らない）
- ただし**道路が街と繋がっているタイルにしか区画しない** — このチェックが無かったとき、
  自動プレイヤーは川で途切れた道の先を平気で区画し、数百人が職場に行けない街ができた
- 通勤時間が延びたら district 間の道路をもう1本通す（1日1本）
- 赤字になったら税率を上げる

操作はすべて `applyTool`（ツールバーと同じ入口）を通すので、**プレイヤーにできること
しかできず、同じ値段を払う**。

3日ぶんだけ回す。1 tick のコストはだいたい「路上にいる人数」なので、2週間ぶん回すと
分単位になる。3日なら約10秒で、すでに数百人の街を電気・食料・区画・渋滞の面倒を見ながら
育てたことになる。シミュレーションは決定的（シードRNG・壁時計を見ない）で自動プレイヤーも
乱数を使わないので、しきい値は運ではなく安定した値。

確認しているのは、3日目の終わりに:

- 人口が500人を超え、建物が200を超え、しかも**まだ増えている**（初日の2倍以上）
- ほぼ全員が就業していて、幸福度が45を超えている
- 発電所が3基以上あり、電力網から切れた建物がなく、不足が需要の1割未満
- 食料供給率が6割を超え、商店の過半数に在庫があり、一次産業が生きている
- 借金ゼロ・残高プラス（**借入ではなく税収で**建てた街であること）
- 経路なしの市民がほぼゼロ、立ち往生したトラックがゼロ、鉄道に乗客がいる
- 警告ウィンドウに critical が1件も出ていない
- そして自動プレイヤーが実際に手を動かしている（何もしなくなっていたら、
  上の全部は「初期状態の街」を測っているだけになる）

車追従モデルは純関数なので、性質を直接検証している:

- 前方車なしで最高速へ単調収束する（かつ即座には到達しない）
- 停止線を**行き過ぎない**（離散積分での実証）
- 前車が急停止しても**追突しない**
- 速度は加減速の上限を超えて変化しない、`v >= 0`

統合テストでは、同じ需要を1車線と6車線に流し、**1車線側だけが遅くなる**ことを確認する
（渋滞が交通モデル由来であることの検証）。加えて、渋滞が必ず**捌ける**こと、
道路を切断すると市民が `Stranded` になり再敷設で復帰すること、
同一シードで N tick 後の状態が完全に一致すること。

鉄道側は、往復ルートの停車位置が単調増加すること、電車が滑らかに発着すること
（速度変化が加減速上限を超えない）、市民が**待つ→乗る→降りる→歩いて到着**の全行程を
通ること、**渋滞したときだけ**電車に移ること（同じ街から路線を消すと全員が車に戻る）、
踏切が列車の接近時だけ閉まり**逃げ道なしで**車を止めること、路線を撤去すると
乗車中の市民が徒歩に戻ること、鉄道込みでも決定性が保たれることを確認する。

追加分:

- **信号**: 交差点だけに付き曲がり角には付かないこと、1周期で両軸がちょうど1回ずつ
  青になり同時に青にならないこと、道路を作り替えると追従すること、車が赤で停止線に
  止まり青で発進すること、**赤で交差点に入るのは「変わった瞬間に止まれなかった車」
  だけ**であること。
- **路線建設**: 繋がっていない駅を選ぶと線路が敷かれること、既に繋がっていれば
  1タイルも足さないこと、線路のない駅にホームが作られること、水面で繋げないときに
  **1タイルも残さず**失敗すること、敷かれた線路が斜めに飛ばないこと。
- **地形・坂・立体交差**（`terrain.test.ts`）: 生成された高さが範囲に収まり水が谷底に
  あること、開幕の街の敷地が平らなこと、崖が区画から外れること、道路は登れて線路は
  登れないこと、高架にすれば線路も段差を越えられること、登りだけ遅くなり下りは
  変わらないこと（トラックは車より遅くなること）、丘を避けて経路が引かれること、
  高架にすると踏切が消えること（線路側を上げても同じ）、水上の高架が橋になること、
  そして高さと高架がセーブを往復すること。
- **セーブ/ロード**: 往復で完全一致すること、その後の進行も一致し続けること、
  乗車中の乗客が列車に乗ったままであること、版が違うセーブを拒むこと、
  資金・借入・税率・在庫・騒音・地価・幸福度・資源レイヤまで持ち越すこと。
  トラックは**指紋（fingerprint）にも含める** — 同一性テストが見ていない部分は、
  同一性テストが守っていない部分でもある。輸送中の積荷も在庫の合計に数える。
  なお**電力の「通電しているか」はセーブに含める**。電力網は30分ごとにしか解き直さ
  ないので、直前に建った建物は次の解き直しまで正当に暗い。ロード時に解き直すと
  そこだけ先に点灯し、再開した街が「保存した街」と違うものになる（工場が動き、
  配車が変わる）。実際これで一致が崩れているのを、地形を入れたときに見つけた。
- **物流**: トラックが実際に走って在庫が動くこと、積み込んだ瞬間に供給元から減ること
  （在庫が二重に数えられも消えもしないこと）、道路を切ると配送が止まり棚が空になること、
  トラックが車と同じ占有に登録され**車より広い場所を取る**こと、車両数の上限と1施設
  あたりの上限が効くこと、配送先や車庫が撤去されても**トラックが宙に浮かない**こと。
- **買い物**: 市民が実際に商店へ出かけて帰ってくること、買った分だけ棚が減り商業税が
  生まれること、**深夜には買い物に出ない**こと（夕方に偏ること）、棚が空の商店には
  そもそも出かけないこと、空振りが幸福度に効くこと、無職の市民も買い物に出ること、
  そして産業のない街が**渋滞ではなく空腹**になること。
- **統計**: 市民が必ず1回だけ数えられること、駅ごとの待ち人数の合計が全体の待ち人数と
  一致すること（マップのバッジとパネルが同じ数を出す保証）、移動は**完了してから**
  計上されること。
- **車線と向き**: 停止中でも経路から向きが出ること、対向2方向が中心線の反対側に
  分かれること。
- **お金**: 建設が課金され、払えないものは**1円も引かずに**拒否されること、維持費は
  残高がなくても引き落とされること、税が「建てたもの」ではなく「生産されたもの」に
  かかること、税率を上げれば税収が増えること（かつ上限で頭打ちになること）、
  借入・利息・返済が動くこと、そして**まともに作った街は自分で採算が合う**こと。
- **供給網**: 一次産業→工場→商店→住民が実際に流れること、産業と商店を繋ぐ道路を
  切ると**数日かけて棚が空になり**供給率が落ちること、地形の合わない一次産業は
  区画できないこと、漁業は水に接するタイルだけであること。
- **電気**: 発電所は**自分の道路網の建物だけ**を点けること、道路を繋げば追随すること、
  需要が容量を超えれば停電が出ること、停電した街では**供給網も税収も止まる**こと。
- **騒音・地価**: 工業の足元がいちばんうるさく距離で減衰すること、うるさい土地の
  地価が静かな土地より低いこと、どちらの値も 0〜100 に収まること。
- **幸福度・人口移動**: まともな街には人が集まること、電気も仕事も商店も失った街は
  **人口が減る**こと、そのとき id の詰め直しが建物・列車の参照ごと整合すること、
  隣人が出ていっても自分の生活時間が変わらないこと。
- **交差点**（`intersection.test.ts`）: 一度も空かない交差点でも**トラックが車と同じく
  抜けられる**こと（修正前はトラックだけが永久に抜けられなかった）、交差点に入る前に
  減速して鼻先で止まること、譲りの解除を得た車両が**一度で**抜けること、
  直交交通が「追従すべき先行車」として扱われないこと。
- **警告**（`diagnostics.test.ts`）: 停電が在庫切れや人手不足より優先されること、
  発電所は電気の有無だけで判定されること、正常な街には critical が出ないこと、
  電力不足の警告が**行き先タイルを持つ**こと、並び順が緊急度どおりであること。
- **バス**（`bus.test.ts`）: 道路で繋がっていない停留所では開業できないこと、
  開業しても**道路も線路も1タイルも増えない**こと、バスが停留所を順に回ること、
  通勤客を運び終えて徒歩に戻すこと、定員を超えないこと、経路上の道路を撤去しても
  **別の道があれば運行が続く**こと、どうしても繋がらなくなったら廃止してバスを
  解放すること。
- **公共サービス**（`services.test.ts`）: 到達圏が直線距離ではなく**道路をたどる**こと
  （道のない対岸には届かない）、後から道路を繋ぐと追随すること、圏内の世帯だけが
  学歴を得ること、**教員のいない・停電した学校は学校として数えない**こと、
  警察署のある街とない街を同時に走らせて治安の差が出ること、犯罪が地価の内訳に
  減点として現れること。
- **火災・治安**（`emergency.test.ts`）: 誰も来なければ建物が焼失すること、
  消防署があれば消防車が出動して**建物が残る**こと（そして車庫に帰ること）、
  道路が切れていれば出動できず失われること、焼け出された住民が空き家に移るか街を
  出て**立ち往生しない**こと、署ごとに2台配備され撤去で退役すること、
  警察署にはパトカーが配備されること。
- **公園とレジャー**（`leisure.test.ts`）: 市民が実際に施設へ出かけて帰ってくること、
  行き先のない街では**出かけずに不満だけが残る**こと（施設数ではなく満足度で測る）、
  停電した施設・満員の施設には出かけないこと、満員なら**入れずに帰る**こと、
  訪問で余暇が回復し日が経つと減ること、休みの曜日が人ごとにばらばらで毎週同じ日で
  あること、休日の市民が出勤しないこと、そして公園が地価の内訳に加点として現れ
  内訳の合計が場の「落ち着く先」と一致すること。
- **病院と健康**（`health.test.ts`）: 到達圏が道路をたどること、病院がなければ健康が
  下がり、建てて動かせば上がること（学歴と違って**両方向に動く**）、騒音が目標値を
  押し下げること、無料健診条例が目標値を上げること。
- **路線の編集**（`lineEditing.test.ts`）: 改名・色替えが経路に触れないこと、
  増便・減便ができて**最後の1台は減らせない**こと、上限8で止まること、
  減便した車両が**止まってからも走り続けない**こと、経路変更で停留所を足しても
  路線ID・名前・のべ乗車人数が残ること、鉄道なら足りない線路が敷かれること、
  **繋げない経路に変更しようとしたら元のまま**であること、廃止しても停留所は残り
  車両が解放されること、廃止した路線の車両スロットが再利用されること。
- **条例**（`policies.test.ts`）: 初期状態では何も施行されていないこと、
  運賃補助が**モード選択の閾値そのもの**を動かすこと、省エネ条例が街全体の電力需要を
  下げること、請求が街の規模に比例すること（人口・乗車人数）、前日の内訳に
  独立した項目として出ること、**残高が足りなくても引き落とされる**こと、
  緑化条例が公園の地価への効きを強めること。
- **電力レポート・地価の内訳**（`fields.test.ts`）: 不足が**道路網ごと**に数えられること
  （合計が足りていても孤立地区は不足と出る）、道路の無い建物が別枠で数えられること、
  地価の内訳の合計が場の「落ち着く先」と一致し、実際の地価ともほぼ一致すること、
  駅が加点・騒音が減点として現れること。
